# ImportRun accounting

برای هر payload، هر آیتم دقیقاً یک نتیجه دارد:

- `created`: پروژهٔ جدید در MySQL ساخته شد.
- `updated`: پروژهٔ موجود با دادهٔ معتبر جدید به‌روزرسانی شد.
- `skipped`: اعلان غیرپروژه، URL تکراری در همان batch، یا رکورد بدون تغییر بود.
- `rejected`: رکورد پیش از ورود به سرویس به‌دلیل URL/عنوان/ساختار نامعتبر رد شد.
- `failed`: رکورد معتبر بود اما هنگام normalize یا ذخیره‌سازی خطای داخلی رخ داد.

`projects_fetched` مجموع تمام این نتایج برای همان batch است. در endpoint، رکوردهای
`rejected` و `skipped` پیش از dispatch ثبت می‌شوند و سرویس ingestion برای رکوردهای
معتبر شمارنده را افزایش می‌دهد؛ بنابراین رکوردی بی‌حساب باقی نمی‌ماند.

وضعیت نهایی:

- `completed`: هیچ `rejected` یا `failed` وجود ندارد.
- `partial`: حداقل یک نتیجهٔ موفق (`created`/`updated`/`skipped`) و حداقل یک رد یا خطا وجود دارد.
- `failed`: هیچ نتیجهٔ موفقی وجود ندارد یا اجرای کلی job شکست خورده است.

پاسخ HTTP برای `completed` برابر ۲۰۰، برای `partial` برابر ۲۰۷ و برای `failed`
برابر ۴۲۲ است. خطاها فقط برچسب‌های sanitize‌شده هستند و SQL، token، cookie یا
HTML خصوصی را ذخیره نمی‌کنند.
